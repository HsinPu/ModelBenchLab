# 空白回應與逾時診斷

日期：2026-09-25。程式檢查：`check_response()` 對 HTTP 錯誤分類；成功回應若沒有文字，`finish_reason=length` 會歸類為 `no_text_output`；只有 HTTPX 的 TimeoutException 才歸類為 `timeout_uncertain`。這兩條路徑原本沒有保存空白回應的用量和實際模型，且前端「單次逾時」容易誤認為整題總耗時上限。

- 使用者當時正在執行的 Auto Router 941 題測試已有 2 筆 `no_text_output`，各耗時約 64 與 137 秒，Run 設定 `max_tokens` 留空、模型預設 32,768、`timeout=60`。舊紀錄未保存失敗回應的 token 用量、實際模型或 generation ID，因此不能斷定是哪個模型的內部限制或推理用量。根據 HTTPX 文件，60 秒屬單次網路連線／讀寫等待逾時，不是整題總耗時硬上限。
- 新程式對無文字回應保存 allowlist 診斷：HTTP 狀態、結束原因、請求上限、回報輸出／推理 token、實際模型、耗時；對 HTTPX 逾時保存種類、設定秒數與耗時。失敗項目可展開診斷，舊 `no_text_output` 紀錄也明示它不代表網路逾時。未保存原始回應或推理文字。
- 完整後端 pytest：69 passed；前端正式 build、Ruff F、`git diff --check` 通過。當時正式測試仍在執行，未重啟 API / Worker，避免中斷可能計費的請求；新後端診斷要在該測試結束並重啟服務後才會用於後續項目。前端文案由 Vite 即時更新。
